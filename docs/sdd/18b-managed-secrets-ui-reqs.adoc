== Admin UI — Secrets Section

The secrets section is a distinct card rendered above the existing config
fields on `SystemConfigView.vue`. It is loaded on mount via
`GET /api/v1/admin/secrets` (parallel to the existing `GET /api/v1/admin/config`
call).

Each secret row contains:

1. A label: "Anthropic API Key" or "Brave Search API Key".
2. A status badge:
   - Green "Configured (••••LAST4)" when `source == "managed"`.
   - Amber "Set via environment" when `source == "env"`.
   - Red "Not configured" when `source == "none"`.
3. A `<input type="password">` field — always blank on render, never
   pre-filled. Placeholder: "Enter new value to update".
4. A "Save" button that calls `PUT /api/v1/admin/secrets/{name}`.
5. A "Clear" button (visible only when `source == "managed"`) that calls
   `DELETE /api/v1/admin/secrets/{name}` after a confirmation dialog:
   "Remove managed {label}? The environment variable fallback will be used
   if set."

Behaviour:

* The password input is cleared to blank after every successful PUT response.
* The component re-fetches `GET /api/v1/admin/secrets` after each PUT or
  DELETE to refresh badges.
* The `value` from the password input is not stored in component state beyond
  the in-flight PUT request body. Vue's `v-model` on a password input does not
  persist across navigation.
* The "Save" button is disabled while the PUT request is in flight.
* Error messages from failed PUT/DELETE responses are displayed inline.

== Admin UI — Config Key Explanations

Every config key (13 existing keys plus the 2 managed secrets = 15 total)
renders an expandable explanation block below its label. The block is
collapsed by default; a "?" icon button toggles it. Explanation text is
hardcoded in the frontend (not fetched from an API) and maintained alongside
the code.

Explanation content by key:

`agent_retry_limit` (REQ-FEADMIN-513)::
  Controls how many times the AI agent retries a failed Anthropic API call
  before giving up. Each retry waits longer than the last (exponential backoff
  with jitter). Default: 3. Minimum: 1. Higher values reduce outright failures
  during API congestion but increase the time a student waits for a response.

`correction_loop_max_iterations` (REQ-FEADMIN-513)::
  Limits how many times the Reviewer agent sends a generated section back to
  the Professor for revision before escalating to an admin notification. Default:
  5. Minimum: 1. Raising this value may improve content quality at the cost of
  longer generation time.

`per_student_token_limit` (REQ-FEADMIN-513)::
  Maximum cumulative AI tokens (input + output) allowed per student per course.
  Default: 500000. Set to 0 to disable the limit entirely. Enforced before every
  AI call; once reached, all AI features are halted for that student's course.

`late_penalty_rate` (REQ-FEADMIN-514)::
  Fraction of a submission's raw score deducted for each calendar day it is
  late. Default: 0.05 (5% per day). Valid range: 0.0 to 1.0 inclusive. A value
  of 0.0 disables late penalties.

`homework_weight` (REQ-FEADMIN-514)::
  Share of the final course grade contributed by homework scores. Must be
  positive and sum to exactly 1.0 with `project_weight`. Default: 0.7.

`project_weight` (REQ-FEADMIN-514)::
  Share of the final course grade contributed by the final project score. Must
  be positive and sum to exactly 1.0 with `homework_weight`. Default: 0.3.

`session_inactivity_seconds` (REQ-FEADMIN-515) — RESERVED::
  *Changing this value has no effect on the running server.* The inactivity
  timeout is read from the `AUTH_INACTIVITY_PERIOD` environment variable at
  startup. This key is stored and validated so future wiring can activate it
  without a migration. Default: 1800 (30 minutes). Minimum: 1.

`account_lockout_seconds` (REQ-FEADMIN-515) — RESERVED::
  *Changing this value has no effect on the running server.* The lockout
  duration is read from the `AUTH_LOCKOUT_DURATION` environment variable at
  startup. This key is stored and validated so future wiring can activate it
  without a migration. Default: 900 (15 minutes). Minimum: 1.

`max_upload_bytes` (REQ-FEADMIN-515)::
  Maximum size in bytes of a single homework submission file. Default: 10485760
  (10 MiB). Minimum: 1024. Files larger than this are rejected before disk
  write. Changes take effect immediately for new uploads.

`content_generation_timeout_seconds` (REQ-FEADMIN-513)::
  Maximum time for the full section-generation pipeline per course. Default:
  300 (5 minutes). Minimum: 1. If generation does not complete within this
  window, the run is cancelled and the student is notified.

`audit_retention_days` (REQ-FEADMIN-512) — NO PURGE WORKER::
  *No automated purge is currently implemented.* This key is stored and
  validated but no background worker reads it to delete aged audit entries.
  The audit log is append-only by design (the `valory_app` DB role holds no
  DELETE privilege on `audit_log`). This key is a placeholder for a future
  retention worker. Default: 365. Minimum: 1.

`notification_retention_days` (REQ-FEADMIN-513)::
  Notifications older than this many days are deleted by a background worker
  that runs every 24 hours. Default: 90. Minimum: 1. Changes take effect at
  the next worker cycle.

`consent_version` (REQ-FEADMIN-515)::
  The current AI data-sharing consent version string (e.g. "1.0", "2.0").
  Any student whose stored consent version is lower than this value must
  re-accept consent before accessing any protected endpoint. Bumping this
  value is a gate action — plan it carefully, as it immediately blocks all
  students who have not yet accepted the new version. Admins are exempt.

`anthropic_api_key` managed secret (REQ-FEADMIN-516)::
  The Anthropic API key used to call Claude for all AI features — content
  generation, grading, and chat. If set here, this value takes precedence
  over the `ANTHROPIC_API_KEY` environment variable. If neither is set, all
  AI features will fail at runtime. Changes take effect within 30 seconds
  without a container restart.

`brave_api_key` managed secret (REQ-FEADMIN-516)::
  The Brave Search API key used to ground lesson content in current internet
  search results. If absent (neither managed nor env var), web search
  grounding is silently skipped and the Professor generates content without
  internet context. Changes take effect within 30 seconds without a restart.

== CLAUDE.md Convention Amendment

Replace the bullet "Secrets and API keys come from environment variables
only — never hardcoded" in the Key conventions section with:

____
Secrets and API keys come from environment variables by default and must never
be hardcoded. The `VALORY_SECRET_KEY` environment variable (a 32-byte
base64-encoded master key set once at install) enables the managed-secrets
subsystem, which allows admins to supply `ANTHROPIC_API_KEY` and `BRAVE_API_KEY`
via the admin config UI. When set via the UI, managed secrets are stored
AES-256-GCM encrypted in the `managed_secrets` table. The managed secret takes
precedence over the env var; if `VALORY_SECRET_KEY` is absent or invalid, the
system falls back to env vars and logs a single WARN at startup without crashing.
No plaintext secret value may appear in source code, logs, audit payloads, or
any HTTP response body.
____

== e2e Implications

Test-author is responsible for implementation; this section provides the spec.

*Scenario 1 — Key entry displays status; value never echoed*

1. Admin navigates to Config page.
2. Secrets section shows "Not configured" for `anthropic_api_key`.
3. Admin types a test value into the password field and clicks Save.
4. Assert: `PUT /api/v1/admin/secrets/anthropic_api_key` returns HTTP 200.
5. Assert: Password input field is blank after save.
6. Assert: Badge shows "Configured (••••LAST4)".
7. Assert: `GET /api/v1/admin/secrets` response body does NOT contain the test value.
8. Assert: No API response body from any admin endpoint contains the plaintext value.

*Scenario 2 — Clear reverts to env fallback*

1. Start with a managed secret present (from Scenario 1).
2. Admin clicks Clear; confirmation dialog appears.
3. Admin confirms.
4. Assert: `DELETE /api/v1/admin/secrets/anthropic_api_key` returns HTTP 204.
5. Assert: Badge shows "Set via environment" (if env var is set in test
   environment) or "Not configured".
6. Assert: `managed_secrets` table has no row for `anthropic_api_key`.

*Scenario 3 — Resolution order: managed beats env*

1. Set `ANTHROPIC_API_KEY` env var to sentinel value "env-key-sentinel".
2. Set managed secret to a different value via PUT.
3. Trigger an AI call against the test Anthropic mock.
4. Assert: mock received `Authorization: Bearer <managed-value>`, not
   `env-key-sentinel`.

*Scenario 4 — Value absent from all API responses*

After PUT with a known test value, sweep all admin API endpoints and assert
the plaintext test value does not appear in any response body.
