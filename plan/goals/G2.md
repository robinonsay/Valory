# G2 — Phase B: interactive knowledge-tree epic

> Level 1. Owned by `project-manager`. Worked example (Sprints 27–30). Largest item;
> opens with a design + requirements contract sprint before any production code.

## Outcome

Re-architect course generation as an interactive knowledge tree (DAG) with a human-in-the-loop
checkpoint at each level — root (course intent) → syllabus → per-section goals → concepts →
content — usable by both admins (authoring/assigning) and students (building). Subsumes the
admin-authoring half of ask 4.

## Acceptance

- A knowledge-tree data model coexists with legacy flat courses (no piecemeal migration).
- Generation advances layer by layer, pausing at each HITL checkpoint for approve / feedback /
  regenerate.
- Admins and students interact with the Chair per node.
- Existing flat courses keep working; paid-API cost/throttle implications are reviewed.
