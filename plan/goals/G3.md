# G3 — Generation execution substrate: bounded, cost-governed, resilient runs

> Level 1. A major outcome that helps satisfy the root ask. Owned by `project-manager`.

## Outcome

Replace the fire-and-forget, poll-driven course-generation model with a disciplined **run
lifecycle** so generation (flat *and* tree) is **idempotent**, **bounded** (retry / backoff /
circuit-break), **cost-governed** (Anthropic *and* Brave budgeted and pre-flighted), and
**resilient** (bounded-concurrency, resumable, per-section deadlines). This eliminates the three
failure modes a single demo session exposed — runaway re-triggering (925 failed runs in 10h),
runaway external-API spend (~1000 Brave calls, an exhausted key), and chronic timeouts (300s coarse
deadline) — with **no regression** to existing flat or tree courses.

Why it matters to the root ask: ask #5 (interactive knowledge-tree generation) and the existing
flat-course flow both depend on the same generation engine. Today that engine is not safe to run —
it can storm the database, exhaust paid API quotas, and rarely completes. No oversight or
interactive-tree feature is trustworthy until the execution substrate beneath it is.

## Acceptance

Observably true when this goal is met:

1. **No storm.** Under a persistently-failing course, the number of generation runs started in any
   window is bounded by an explicit retry policy (backoff + max-attempts), not the poll interval.
   A failing course reaches a terminal `generation_failed` state instead of re-triggering forever.
2. **No double-run.** Dispatch is idempotent: a course never has two concurrent generation runs
   (flat or tree), proven under a forced race — not reliant on an incidental status default.
3. **Cost pre-flight.** No run makes *any* paid external call (Anthropic or Brave) once it is over
   its token/cost budget; an over-budget run fails before its first section.
4. **Brave is accounted + capped.** Brave Search calls are counted and bounded per run (≤ a
   configured cap); a doomed run makes zero Brave calls.
5. **Completes + resumes.** A typical multi-section course completes within a target wall-clock via
   bounded concurrency; a retried run does not redo already-approved sections.
6. **Backward compatible + gated.** Existing flat-course and tree-course generation still work; all
   changes pass the acceptance facet (SQE + Systems Engineer → Senior SQE) and preserve RLS/role
   context.

(cost gating and concurrency both attach to lifecycle hooks). S2/S3 are **provisional** — decomposed
into tasks only when each becomes the active frontier (mirrors how G2-S2..S4 were sequenced).

operations (the DeleteStudent / syllabi bare-pool class). Same root disease — "risky operations lack
enforced invariants" — but a distinct surface. Track as **candidate G4** (RLS/role-context
enforcement + kill superuser test-masking) so G3 stays focused on generation execution.
