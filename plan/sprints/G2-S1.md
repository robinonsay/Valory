# G2-S1 — DESIGN + REQUIREMENTS contract for the interactive knowledge tree (Sprint 27)

> Level 2, goal G2. Owned by `software-lead`. **No production code.** This sprint is itself a
> PM/Senior-SQE decision gate — the Senior SQE reviews the *design* before any implementation
> is authorized. G2-S2…S4 stay provisional until this lands.

## Scope

Produce the design + requirements contract that every later Phase B sprint builds against:
the knowledge-tree DAG data model, the layered generation state machine with per-level HITL
checkpoints, the node-level Chair interaction API/SSE spec, and the derived L1/L2 requirements.

## Tasks (level 3)

| Task | Increment | Worker | Verifier (acceptance) | Depends on |
|------|-----------|--------|-----------------------|------------|
| G2-S1-T1 | TDD: knowledge-tree DAG data model (`course_nodes`: id, course_id, parent_id, node_type, ordering, status, payload; coexistence with legacy tables; migration strategy) | design-author | Senior SQE | — |
| G2-S1-T2 | TDD: layered generation state machine + per-level HITL checkpoint protocol; how it wraps/replaces the flat `generateAllSections` loop | design-author | Senior SQE | — |

| G2-S1-T4 | L1 + L2 requirements derived from the TDDs (new `course_nodes`/orchestration module reqs; legacy L1 stays central) | requirements-author | Senior SQE | G2-S1-T1, G2-S1-T2, G2-S1-T3 |

## Dependencies / sequencing

T1–T3 are independent design facets and run in parallel; T4 depends on all three. Decompose
into task files when this sprint becomes the frontier.

## Requirements in scope

New `course_nodes` / orchestration module requirements authored in T4; legacy L1 stays in
`requirements/l1-requirements.json`.

## Definition of done

The design contract passes the Senior SQE gate. Only then are G2-S2…S4 decomposed and may be
re-scoped against the approved design.
