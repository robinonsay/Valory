# G2-S2 — Knowledge-tree backend foundation (Sprint 28)

> Level 2, goal G2. Owned by `software-lead`. The first **production-code** sprint of Phase B.
> Builds against the approved G2-S1 design contract (3 TDDs + REQ-AGENT-027..060 / REQ-SYS-072..077).

## Scope

Lay the durable foundation the layered orchestrator (G2-S3) and the interactive frontend
(G2-S4) build on: the complete tree schema (one migration), the two node repositories
(student `course_nodes` and admin `course_drafts`/`draft_nodes`), and DB integration tests
proving CRUD + RLS isolation under `SET ROLE valory_app`. **No orchestrator, no Chair
generalisation, no HTTP handlers, no frontend** — those are G2-S3 / G2-S4.

The "state machine" in this sprint means the **durable status-transition repository methods**
(atomic test-and-set guards, layer-aggregate queries) — not the `LayeredRunner` poller, which
is G2-S3.

## Lead decisions on G2-S1 design open questions (binding for this sprint)

The design docs left open questions for the Lead. Resolved here so workers have an
authoritative contract:

| # | Question (source) | **Decision** |
|---|---|---|
| D1 | Migration number (collision: G1-S2 also uses 021) | Phase B migration is **`022_tree_generation.sql`**. G1-S2 keeps `021_admin_oversight_rls.sql`. |
| D2 | Deploy cross-course parent-guard trigger? (data-model §4.4/§10.1) | **Yes — deploy it.** Negligible per-write overhead; high safety value during early development. Applies to `course_nodes` and `draft_nodes`. |
| D3 | tree-mode enable flag: DB config row vs env var (data-model §10.2) | **DB `system_config` row** `enable_tree_mode_courses` (default `false`), consistent with `correction_loop_max_iterations` etc. No env var. |
| D4 | `course_drafts` lifecycle status (api-sse §10.6) | `course_drafts.status` stays **TEXT** (`draft`/`published` plus poller variants `generating`/`awaiting_layer_approval`/`awaiting_regeneration` as text — no enum). **Add `current_layer node_type_enum` column** to `course_drafts`, mirroring `courses.current_layer`. |
| D5 | `assignments.draft_id` (api-sse §7.2) | **Add nullable `draft_id UUID REFERENCES course_drafts(id)`** to `assignments` in this migration (column only; the publish/copy logic is G2-S3). |
| D6 | Flat-table compatibility double-write (data-model §10.3) | **Deferred to G2-S3** (agent integration). The migration keeps the `syllabus_id`/`lesson_content_id` payload cross-link fields available but writes nothing to flat tables. Not a G2-S2 concern. |
| D7 | tree-mode immutability (state-machine §12.1) | `tree_mode` is **set at course/draft creation and is immutable after the first node is generated**. Enforcement lives in G2-S3 handlers; the schema does not need a trigger for it. |
| D8 | per-node `tokens_used` reporting column (state-machine §8.3) | **Include** nullable `tokens_used INT` on `course_nodes` (additive reporting column; populated by G2-S3). |
| D9 | `agent_token_usage` index rename (data-model §10.5 / §4.7) | The migration **must introspect the actual existing unique index/constraint name** before `DROP` — do not assume `agent_token_usage_student_course_idx`. Use `IF EXISTS` and verify against `003_course.sql`. |

**Outcome:** the knowledge-tree backend foundation is in place — full schema (`course_nodes`,
`course_drafts`, `draft_nodes`, `node_chats`, ALTERs, enums, RLS, parent-guard triggers,
`enable_tree_mode_courses`), two connection-agnostic node repositories, and live RLS integration
tests for both. **Everything verified live against a real PG16 under `SET ROLE valory_app`.**

**The acceptance pipeline caught, before any G2-S3 code built on the schema:** (1) a
runtime-fatal missing `course_nodes` server-SELECT policy; (2) three missing indexes
(`agent_runs.draft_id`, `draft_nodes` ×2); (3) an RLS connection-leak in `DeleteDraft`
(re-resolved `r.conn(ctx)` → bare pool); (4) a non-atomic `SetDraftNodePayload`; and (5) **D10**
— `course_nodes_student_policy` was `FOR ALL` (students could write/self-approve their own
nodes), hardened to `FOR SELECT` to match the design prose and the server-controlled HITL model.

**Design reconciliation (rev 3 / D10):** `docs/design/knowledge-tree-data-model.md` §6 DDL was
self-contradictory (no `FOR` clause → `FOR ALL`, contradicting its own prose note 3); corrected
in the doc to `FOR SELECT` to match the shipped migration.

**Binding instructions carried into G2-S3 (the caller):** all `course_nodes`/`draft_nodes`
writes run on the **server pool** (students are read-only post-D10; the HITL approve/feedback
handlers must UPDATE via the server role after an ownership check); **tx-wrap** `CreateDraft`'s
draft+root insert (`db.Querier` can't `BEGIN`); validate status strings before
`TransitionStatus`/`UpdateStatus` (the draft tables use TEXT, not enums).
