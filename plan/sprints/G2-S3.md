# G2-S3 — Layered orchestrator + Chair node interaction + HITL API (Sprint 29)

> Level 2, goal G2. Owned by `software-lead`. **Provisional** — decomposed into task contracts
> only when it becomes the active frontier (after G2-S2 lands and passes). Delivers root-ask
> **#3** (admin can preview + co-develop a course with the Chair before assigning).

## Scope

Build the runtime on top of the G2-S2 foundation: the layer-by-layer generation engine that
pauses at each HITL checkpoint, the Chair generalisation (`GenerateNode`/`RefineNode`), and the
full HITL HTTP + SSE surface for both the student-building and admin-authoring paths. Backend
only — the Vue UX is G2-S4. Authoritative design: the three `docs/design/*` TDDs.

## Lead decisions (binding for this sprint)

| # | Decision |
|---|---|
| **D11** | The poller-driven `LayeredRunner` handles the **student `course_nodes` path only**. The **admin draft path** generates via direct background goroutines calling `Chair.GenerateNode` (single-node generate AND layer-expand: the admin expand handler enqueues a goroutine per inserted child draft_node). This decouples the admin handler task from the runner task and avoids making `LayeredRunner` generic over two node stores. Supersedes api-sse §5.1.11's "admin expand → poller" suggestion. |
| **D12** | **All `course_nodes`/`draft_nodes` writes run on the server pool** (`app.current_role='server'`). Students are read-only on `course_nodes` post-D10; the HITL approve/feedback/expand handlers do an explicit ownership check on the request-scoped conn, then perform the status/payload UPDATE via the server pool. Admin handlers likewise verify draft ownership then write as server. |
| **D13** | `CreateDraft`'s draft+root insert and the publish→`course_nodes` copy must be **transaction-wrapped** by the caller (the repos take `db.Querier`; the handler/service opens the tx). |
| **D14** | Per-layer token budget (`per_layer_token_budget`, default 0=disabled) is enforced in `LayeredRunner.GenerateLayer` (student path) per state-machine §8.3. Admin draft generation is also subject to the global token cap via `ThrottledClient`. Systems Engineer must review **paid-API cost** (REQ-SYS-074; ~7× call multiplication) on T2 and T4. |
| **D15** | **One generation engine for node content.** `LayeredRunner.GenerateLayer` (T2) generates each node's initial content via **`Chair.GenerateNode`** (T1's node-type-aware prompts), then runs the existing **reviewer** correction/escalation loop for quality — it does NOT call `professor.GenerateSection` (built for flat lesson content; cannot shape `section_goal`/`concept`). This unifies prompts across the interactive (handler, `Chair.GenerateNode`) and bulk (runner) paths so node content is consistent regardless of which path produced it. Supersedes state-machine §5.1's "reuse professor↔reviewer" wording for the *generation* step (the *review* machinery is still reused). The flat-course `generateAllSections`/`runReviewLoop` path stays untouched for `tree_mode=false` courses. |
| **D15a** | **Reviewer loop only for `content` nodes** (refines D15; from the T2 gate). The citation/quality reviewer was built for prose lesson content with citations. `section_goal` and `concept` nodes are structured JSON (no citations) — running the citation reviewer on them makes them always fail and escalate. So the reviewer correction/escalation loop applies **only to `content` nodes**; `section_goal`/`concept` are generated by `Chair.GenerateNode` and go straight to `awaiting_review` (their review *is* the human HITL gate). `root`/`syllabus` remain pre-seeded `approved`. |
| **D15b** | **`settleLayer` ≠ `LayerAggregate` semantics** (from the T2 gate). `LayerAggregate` (G2-S2-T2) buckets `awaiting_review` into `Pending` — correct for `ExpandToNextLayer`'s precondition (awaiting_review must block expansion) but WRONG for `settleLayer`, which must treat `awaiting_review` as *settled* (ready for the HITL gate). `settleLayer` uses its own count where only `pending`+`generating` are in-flight (`awaiting_review` settled). Keep this query in `layered_runner.go` or as a purely-additive tree-repo method that does NOT change `LayerAggregate`. |

## Dependencies / sequencing

Serial after G2-S2. Waves: **T1 → T2 → T3 → (T4 ∥ T5) → T6**. The T1→T2→T3 chain is inherent
(Chair → engine → handlers). T4 (admin) is logically independent of T2/T3 but is **serialised
after T3** because both edit `cmd/server/main.go` (one-worker-per-file-set); meanwhile T5
(student/runner tests, `internal/agent/`) runs in parallel with T4. T6 (admin tests) follows T4.
Honor "one worker per file-set"; T1/T2/T3/T5 are all in package `agent` but on disjoint files —
never two in flight on the same file.

**Outcome:** the interactive knowledge-tree runtime is in place — Chair `GenerateNode`/`RefineNode`
(node-type-aware), the poller-driven `LayeredRunner` (student path, layer-by-layer with HITL
pause), and the full HITL HTTP/SSE surface for **student-building** (`/courses/{id}/nodes…`,
`/layers/{layer}/expand`) and **admin-authoring** (`/admin/drafts…` + publish→assign copy). Asks
**#3** (admin co-develops with the Chair before assigning) and the **#5** engine are delivered.

**Lead decisions made during the sprint:** D11 (admin path goroutine-driven, not poller), D12
(all node writes on the server pool after ownership check — students/admins read-only via RLS),
D13 (tx-wrap CreateDraft + publish copy), D14 (per-layer token budget), D15/D15a/D15b (one
generation engine via `Chair.GenerateNode`; reviewer loop only for `content` nodes;
`settleLayer` ≠ `LayerAggregate` semantics).

**The acceptance pipeline caught, before delivery:** the `settleLayer` showstopper (HITL gate
never reached), a latent migration-022 student-token-accounting regression (`client.go` referenced
a dropped constraint), a token-budget escape in the correction loop, an unbounded admin-expand
goroutine fan-out, and a **corrupt-tree bug in publish→assign** (`ORDER BY ordering` mis-remapped
`parent_id` for every draft-assigned student). All fixed and test-guarded.
