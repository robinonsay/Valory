# G3-S3 — Latency & resilience: concurrency, resumability, per-section deadlines (Sprint 33)

> Level 2, goal G3. Owned by `software-lead`. **Provisional** — decomposed into task contracts
> only when it becomes the active frontier (after G3-S2 lands). Builds on the S1 lifecycle and S2
> cost governance.

## Problem this sprint fixes

`generateAllSections` runs sections **strictly sequentially**, each = one Claude generate call
(`professor_max_tokens` 16384, Sonnet, ~tens of seconds) + a review call + possible regenerations,
all under a **single coarse wall-clock timeout** (`content_generation_timeout_seconds`, found at
300s). Consequences:

- A typical 5–8 section course exceeds 300s and **fails wholesale** (27 timeouts observed), then —
  pre-S1 — re-triggers. Even with a longer timeout, latency is poor (minutes of nothing).
- A timed-out/failed run **redoes everything** on retry (no partial-progress persistence), so cost
  and latency compound.
- The review-loop iteration counter is **run-level** (`IncrementIteration(runID)`), which both
  conflates per-section budgets and would race under any concurrency.

## Scope (tasks decomposed when frontier)

- **Bounded-concurrency generation:** generate sections via a worker pool (small N), respecting the
  S2 cost budget and the S1 lifecycle; replace the single coarse timeout with an overall budget +
  **per-section deadlines**.
- **Resumable / partial progress:** persist per-section completion (lesson_content already
  versioned) and on retry **skip already-approved sections** — don't redo or re-pay for them.
- **Concurrency-safe review loop:** make the correction-iteration counter **per-section** and safe
  under parallelism (no shared run-level mutable counter race).
- **Latency target + observability:** define and assert a target wall-clock for a representative
  course; emit per-section timing.
- **Tests:** parallel generation correctness, resume-skips-approved, per-section deadline, no
  review-counter race, no regression to single-section/tree paths.

## Requirements in scope

`REQ-AGENT-007/008` (review loop — re-scoped per-section), `REQ-AGENT-014` (timeout → per-section +
overall budget), new `REQ-AGENT-*` for concurrency + resumability.

## Definition of done (provisional)

A representative multi-section course completes within target wall-clock; a retried run skips
approved sections; review counters are per-section and race-free; flat + tree generation still
correct. Closes G3 → final combined acceptance facet over the goal.
