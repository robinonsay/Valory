## Design (how — the mandate)

`Service.DeleteStudent` ([internal/user/service.go:245](../../internal/user/service.go#L245))
terminates agent work, then `Repository.DeleteStudent`
([internal/user/repository.go:263](../../internal/user/repository.go#L263)) deletes
submissions → grades → chat_messages → courses → sessions → users in one tx. The tx violates
the FK `agent_runs.course_id` (`ON DELETE RESTRICT`,
[migrations/004_agent.sql:63](../../migrations/004_agent.sql#L63)) for any student who ever had
a generation run, because the repo never deletes `agent_runs` before `courses`.

Fix: inside the **existing transaction**, delete `agent_runs` (and any other RESTRICT-linked
child of the student's courses — check `pipeline_events`) before `DELETE FROM courses`. Keep
ordering correct for all FKs. Preserve RLS/role correctness: use the request-scoped connection
and verify behavior under `SET ROLE valory_app` (the test DB superuser masks RLS bugs — memory
`force-rls-superuser-test-masking`).
