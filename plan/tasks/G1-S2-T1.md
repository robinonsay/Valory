## Design (how — the mandate)

Author the requirement(s) that govern **read-only** admin oversight of a student's full course
material: syllabus, sections, lesson content, homework + rubric, submissions, grades. This is
PM decision #2 — oversight is read-only; admin editing/regeneration is deferred to G2's
interactive flow. The requirements must:

- Scope the admin read surface to the child tables: `syllabi`, `homework`, `lesson_content`,
  `submissions`, `grades` (and, where relevant, `chat_messages`).
- State the RLS invariant explicitly: an admin may read **any** student's material; a student
  must **not** be able to read another student's material (isolation preserved). Acceptance
  must require verification under `SET ROLE valory_app` (the test DB superuser masks RLS bugs —
  memory `force-rls-superuser-test-masking`).
- Prohibit any mutation path in this requirement (no admin edit/regenerate/delete of content).
- Number without collision: backend `REQ-ADMIN-011` (existing ADMIN block ends at 010);
  frontend `REQ-FEADMIN-707` (existing FEADMIN oversight block 700–706 in use).

Place files per CLAUDE.md: new L2 reqs co-located with their module
(`internal/admin/requirements/`). Validate against `schemas/requirements.schema.json`.

## Requirements (what-for)

- Produces **REQ-ADMIN-011** (backend read-only oversight) and **REQ-FEADMIN-707** (admin
