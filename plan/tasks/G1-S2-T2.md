## Design (how — the mandate)

Expose a **read-only** admin oversight read path over a student's course material.

**RLS — the precise gap (verified at decomposition time):**
- `lesson_content` already has `lesson_content_admin_policy` ([004_agent.sql:188](../../migrations/004_agent.sql#L188)) ✓
- `grades` already has `grades_admin_select_policy` ([008_grade.sql:50](../../migrations/008_grade.sql#L50)) ✓
- `chat_messages` already has `chat_messages_admin_policy` ([004_agent.sql:110](../../migrations/004_agent.sql#L110)) ✓
- **`syllabi`, `homework`, `submissions` have NO admin policy** — student/server-scoped only.

So this task **adds a new idempotent migration `021_admin_oversight_rls.sql`** creating
**read-only (USING-only, no WITH CHECK / SELECT-scoped)** admin policies for exactly
`syllabi`, `homework`, and `submissions`, mirroring the `current_setting('app.current_role',
true) = 'admin'` idiom and the `NULLIF`-guard pattern (memory `force-rls-superuser-test-masking`;
006/007/008 NULLIF guard). Do **not** grant admin INSERT/UPDATE/DELETE on any of them.

**Endpoint:** add `GET /admin/courses/{id}/overview` (read-only) returning the aggregated
material for one course — syllabus, sections/lesson_content, homework + rubric, submissions,
grades. Mount it under the existing admin role + CSRF group alongside
`adminConfigHandler`/`assignmentHandler` ([cmd/server/main.go:496-528](../../cmd/server/main.go#L496)),
gated by `auth.RequireRole("admin")`. Reads must go through a connection carrying
`app.current_role='admin'` (same idiom as the assignment path,
[main.go:327-333](../../cmd/server/main.go#L327)). No mutation handlers.
