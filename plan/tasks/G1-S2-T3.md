# G1-S2-T3 — Backend tests: admin oversight read + RLS isolation

> Level 4 task contract. Owned by `software-lead`.

- **Worker:** test-author
- **Verifier (acceptance gate):** SQE
- **Depends on:** G1-S2-T2
- **Artifact path:** `internal/admin/*_test.go` (DB integration test, `-tags testing`);
  summary under `plan/artifacts/G1-S2-T3/`

## Design (how — the mandate)

Add DB integration tests (real Postgres via Docker, no mocks per CLAUDE.md) for the admin
oversight read path. Tests **must** run under `SET ROLE valory_app` so RLS is actually
enforced (the test DB superuser otherwise masks RLS bugs — memory
`force-rls-superuser-test-masking`). Run with `-p 1` to avoid the known DB-test parallelism
drift (memory `valory-db-test-drift`); gate behind `TEST_DATABASE_URL`.

Cases:
- Seed two students, each with a course + syllabus + homework + lesson_content + a submission +
  a grade.
- **Admin** can read either student's full material via `GET /admin/courses/{id}/overview`.
- **Student A** cannot read Student B's `syllabi`/`homework`/`submissions`/`grades`/
  `lesson_content` (isolation preserved) — assert empty/denied under the student role.
- Negative: a non-admin hitting the oversight endpoint is rejected.

## Requirements (what-for)

- **REQ-ADMIN-011**. Test functions annotated `@{"req", ["REQ-ADMIN-011"]}`.

## Acceptance (done-criteria)

- [ ] Admin-reads-any-student test passes under `SET ROLE valory_app`.
- [ ] Student-to-student isolation test passes (B's material invisible to A) under
      `SET ROLE valory_app`.
- [ ] Non-admin is rejected at the endpoint.
- [ ] Tests pass with `-p 1` and `TEST_DATABASE_URL` set; no DB mocks.
