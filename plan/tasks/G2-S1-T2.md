## Design (how — the mandate)

Produce a TDD for the **layered, human-in-the-loop generation state machine** that grows the
knowledge tree one level at a time and **pauses at each level for human review** instead of
running to completion.

Loop per level: `generate layer → persist nodes (awaiting_review) → PAUSE → human
approve / give feedback / regenerate → on approve, expand the next layer`. Cover:

- The per-node and per-layer state transitions (tie to the `status` field from G2-S1-T1).
- **How this wraps or replaces the current flat one-shot loop:** `generateAllSections`
  ([internal/agent/runner.go:397](../../internal/agent/runner.go#L397)) and the professor↔reviewer
  `runReviewLoop` ([runner.go:467](../../internal/agent/runner.go#L467)). Decide: reuse the
  professor/reviewer agents per node vs. rework them. Today's HITL is post-hoc
  `section_feedback` keyword polling ([runner.go:246](../../internal/agent/runner.go#L246)) — the
  new model replaces that with explicit per-level checkpoints.
- **Resumability/durability:** generation must survive a server restart mid-tree and resume
  from the last approved layer (state lives in `course_nodes.status`, not memory).
- **Backward compatibility:** flat courses keep using the existing runner path unchanged.
- **Paid-API cost model:** layered generation multiplies Anthropic calls and changes token-cap
  accounting (`REQ-AGENT-011` token cap, `agent_token_usage`). Document the cost/throttle
  implications and a mitigation (e.g. cap per layer, reuse cached context). This is the input
  the Systems Engineer reviews for cost in G2-S3.
