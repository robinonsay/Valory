## Design (how — the mandate)

Produce the API + SSE specification for interacting with the knowledge tree, for **both
admins (authoring/assigning) and students (building)** — this delivers the admin slice of
root-ask #3 (admin can preview a syllabus and co-develop a course with the Chair before
assigning).

Specify:
- **Per-node Chair interaction** — chat/refine against a single node so a human can add context
  and guide generation. Generalize the existing Chair entry points
  (`GenerateSyllabus` [internal/agent/chair.go:131](../../internal/agent/chair.go#L131),
  `GenerateSyllabusFromParams` [chair.go:191](../../internal/agent/chair.go#L191)) into a
  node-scoped `GenerateNode` / `RefineNode` shape.
- **HITL endpoints:** approve / feedback / regenerate per node (verbs over `course_nodes`).
- **Node-scoped SSE event stream** for live generation progress, mirroring the existing
  pipeline-event SSE idiom.
- **Two entry points with distinct authz:**
  - *Admin-authoring*: an admin co-develops a course/syllabus **before** it is assigned — note
    today assignment generates the syllabus synchronously from params with no preview
    ([internal/admin/assignment_service.go](../../internal/admin/assignment_service.go), mounted
    at [cmd/server/main.go:526](../../cmd/server/main.go#L526)). The spec must define how the
    interactive draft becomes an assignable course.
  - *Student-building*: a student grows their own course level by level.
- **Security / RLS (Systems Engineer gate):** every endpoint's authz, who may act on whose
  nodes, CSRF, and how admin-authoring drafts are isolated. Must compose with the
  `course_nodes` RLS from G2-S1-T1.
