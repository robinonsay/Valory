# G2-S1-T4 — L1 + L2 requirements derived from the TDDs

> Level 4 task contract. Owned by `software-lead`. The contract every Phase B sprint builds on.

- **Worker:** requirements-author
- **Verifier (acceptance gate):** Senior SQE
- **Depends on:** G2-S1-T1, G2-S1-T2, G2-S1-T3
- **Artifact path:** new module requirement files (e.g. `internal/agent/requirements/REQ-AGENT-0xx.json`
  for orchestration, a `course_nodes` module dir for the tree) + any L1 entry in
  `requirements/l1-requirements.json`; summary under `plan/artifacts/G2-S1-T4/`

## Design (how — the mandate)

Derive the L1 (system-level) and L2 (module-level) requirements from the three approved TDDs
(T1 data model, T2 state machine, T3 API/SSE). These requirements are the contract G2-S2…S4
build against; they are authored only after T1–T3 pass the Senior SQE design gate.

- **L2 (module) requirements** co-located per CLAUDE.md (`<module>/requirements/REQ-<MODULE>-<NNN>.json`):
  the knowledge-tree data model + RLS, the layered orchestrator + HITL state machine, the
  node-level Chair interaction, and the HITL/SSE API. Choose module prefixes that don't collide
  with existing ids (AGENT ends at 026; CONTENT, COURSE in use).
- **L1 (system) requirements** stay central in `requirements/l1-requirements.json` (legacy L1
  is not migrated — CLAUDE.md): cover the cross-cutting invariants — backward compatibility with
  flat courses, HITL-at-every-level, paid-API cost governance, RLS isolation for tree nodes.
- Every requirement needs acceptance criteria and traceability back to root-asks #5 and #3.
- All files validate against `schemas/requirements.schema.json`.

## Requirements (what-for)

- Produces the Phase B requirement set. No prior requirement is "implemented" by this task; it
  authors them.

## Acceptance (done-criteria)

- [ ] L2 requirement files authored for: tree data model + RLS, layered orchestrator + HITL,
      node Chair interaction, HITL/SSE API — co-located with their modules.
- [ ] L1 cross-cutting requirements added to `requirements/l1-requirements.json` (backward
      compat, HITL-per-level, paid-API cost governance, tree RLS isolation).
- [ ] All files validate against `schemas/requirements.schema.json`; no ID collisions.
- [ ] Each requirement traces to root-ask #5 (and #3) and has acceptance criteria.
- [ ] Passes the Senior SQE gate. **Only then are G2-S2…S4 decomposed.**

## Worker return schema

```
task_id       G2-S1-T4
status        done | blocked | failed
artifact_path <module>/requirements/*.json ; requirements/l1-requirements.json ; plan/artifacts/G2-S1-T4/
acceptance    pass | fail  + which criteria
deviations    <or "none">
```
