### Contents (the complete object list)

**ENUM types (create if not exists):**
- `node_type_enum` — `root, syllabus, section_goal, concept, content`
- `node_status_enum` — `pending, generating, awaiting_review, approved, rejected, failed` (6)

**ENUM value additions (`ADD VALUE IF NOT EXISTS` — must run OUTSIDE the transaction block;
Postgres implicitly commits these):**
- `course_status` += `awaiting_layer_approval`, `awaiting_regeneration`
- `agent_run_type` += `tree_layer_generation`, `node_generation`
- `pipeline_event_type` += the 11 values in state-machine §10 + the node-scoped values in
  api-sse §5.3.5 (`node_generating`, `node_ready`, `node_approved`, `node_rejected`,
  `node_error`, `layer_awaiting_expand`). De-duplicate; add each only once.

**Tables (create if not exists), in FK-safe order — `course_drafts` and `draft_nodes` BEFORE
`node_chats` (node_chats FKs draft_nodes):**
1. `course_nodes` (data-model §4.2) + indexes §4.3 (parent, course+type, sibling-order partial
   unique, one-root partial unique) + `tokens_used INT` nullable (Lead decision D8).
2. `course_drafts` (api-sse §4.1) + `current_layer node_type_enum` column (Lead decision D4).
3. `draft_nodes` (api-sse §4.2).
4. `node_chats` (data-model §4.6 — two nullable typed FKs `course_node_id`/`draft_node_id`,
   each `ON DELETE CASCADE`, `node_chats_exactly_one_owner` CHECK) + the two partial indexes.

**ALTERs:**
- `courses` += `tree_mode BOOLEAN NOT NULL DEFAULT false`, `current_layer node_type_enum`.
- `agent_runs`: relax `course_id` NOT NULL; += `draft_id UUID REFERENCES course_drafts(id) ON
  DELETE CASCADE`; add `agent_runs_context_check` CHECK (exactly one of course_id/draft_id).
- `agent_token_usage`: relax `student_id`/`course_id` NOT NULL; += `draft_id ... REFERENCES
  course_drafts(id) ON DELETE CASCADE`; add `agent_token_usage_context_check` CHECK; replace
  the single unique index with two partial uniques (student+course where draft_id IS NULL;
  draft_id where NOT NULL). **D9: introspect the actual existing index/constraint name from
  `003_course.sql` before `DROP` — do not assume the name; use `IF EXISTS`.**
- `assignments` += `draft_id UUID REFERENCES course_drafts(id)` nullable (Lead decision D5).

**RLS** (ALL new tables): `ENABLE` + `FORCE ROW LEVEL SECURITY`, policies per the design docs.
Every `current_setting('app.current_user_id', true)` comparison MUST use the
`NULLIF(..., '')::uuid` guard (memory `force-rls-superuser-test-masking`). Wrap each
`CREATE POLICY` in `DO $$ BEGIN ... EXCEPTION WHEN duplicate_object THEN NULL; END $$;` for
idempotency. `GRANT` the documented privileges to `valory_app`.

**Parent-guard trigger (Lead decision D2 — DEPLOY):** add the
`course_nodes_check_parent_course()` trigger from data-model §4.4, and an analogous guard for
`draft_nodes` (reject cross-draft parent assignment).

**Config:** insert `enable_tree_mode_courses` into `system_config` default `false` (Lead
decision D3) — match the existing `system_config` insert idiom (idempotent `ON CONFLICT DO
NOTHING` or `WHERE NOT EXISTS`). Check how `correction_loop_max_iterations` is seeded.

### Structure / ordering constraints

- The enum `ADD VALUE` statements cannot run inside a transaction. Structure the file so they
  execute before the `BEGIN ... COMMIT` DDL block (state-machine §13). Verify the runner
  (`migrations/embed.go` + caller) executes the file statement-by-statement or tolerates the
  split; match how prior migrations that add enum values are structured (none may exist — if so,
  keep enum-adds at the top, outside any explicit transaction).
- Idempotent throughout: `CREATE TYPE` guarded (`DO $$ ... duplicate_object`), `CREATE TABLE IF
  NOT EXISTS`, `CREATE INDEX IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS`, `ADD VALUE IF NOT
  EXISTS`, policy guards. Re-running the migration must be a no-op.
- Mirror the 003/004/006/007/008 idiom for RLS, NULLIF guards, and GRANTs exactly.

## Acceptance (done-criteria)

- [ ] `022_tree_generation.sql` creates every object listed above; FK order correct
      (course_drafts/draft_nodes before node_chats).
- [ ] Fully idempotent — running it twice in a row succeeds with no error and no duplicate
      objects. (Demonstrate by applying to a fresh test DB twice.)
- [ ] All existing migrations 001–021 still apply cleanly before it (no fresh-DB break — recall
      the 006/007/008 NULLIF fresh-DB lesson in git history).
- [ ] Every RLS policy on every new table uses the `NULLIF(current_setting(...), '')::uuid`
      guard; `FORCE ROW LEVEL SECURITY` set on all four new tables.
- [ ] `courses`/`agent_runs`/`agent_token_usage`/`assignments` ALTERs are additive and default
      such that existing rows and the flat-course path are unaffected.
- [ ] Enum `ADD VALUE` statements are positioned to execute outside the DDL transaction.
- [ ] Parent-guard triggers deployed for `course_nodes` and `draft_nodes`.
- [ ] `enable_tree_mode_courses` seeded in `system_config` default false, idempotently.
- [ ] No data migration of legacy rows (CLAUDE.md: no piecemeal migration).
