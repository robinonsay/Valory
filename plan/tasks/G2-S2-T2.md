## Design (how — the mandate)

Add a repository for the **student** knowledge-tree (`course_nodes` + the `course_node_id`
side of `node_chats`). This is data-access only — **no orchestrator, no Chair, no HTTP**.
Model it on the existing `internal/agent/repository.go` (`AgentRepository`) conventions:
pgx, `context.Context` first arg, parameterized queries only, request-scoped connection for
RLS-governed reads/writes.

### Required methods (names indicative; match package style)

- `CreateNode(ctx, conn, node) (uuid.UUID, error)` — insert one `course_nodes` row; caller
  supplies `course_id`, `parent_id` (nullable), `node_type`, `ordering`, `payload`. Default
  status `pending`.
- `GetNode(ctx, conn, nodeID) (Node, error)` — single node by id.
- `ListNodesByCourse(ctx, conn, courseID, opts) ([]Node, error)` — with optional `node_type`
  and `parent_id` filters (covers api-sse §5.2.1).
- `ListChildren(ctx, conn, parentID) ([]Node, error)` — ordered by `ordering ASC`.
- `TransitionNodeStatus(ctx, conn, nodeID, from, to) (bool, error)` — **atomic test-and-set**:
  `UPDATE ... SET status=$to, updated_at=now() WHERE id=$id AND status=$from`; return whether
  `rowsAffected == 1`. This is the concurrent-generation guard (api-sse §10.4); a variant that
  guards on `status != 'generating'` for the generate path is acceptable.
- `SetNodePayload(ctx, conn, nodeID, payload)` and/or a combined update used when generation
  completes.
- `LayerAggregate(ctx, conn, courseID, nodeType) (approved, failed, pending int, error)` — the
  settled-layer query from state-machine §4.2.
- `node_chats` (course-node side): `AppendNodeChat(ctx, conn, courseNodeID, role, content)` and
  `ListNodeChats(ctx, conn, courseNodeID) ([]NodeChatMessage, error)` ordered by `created_at`.

### RLS / connection rules

- Reads/writes that must respect student ownership take a **request-scoped connection**
  (the `conn` arg, carrying `app.current_user_id`/`app.current_role` GUCs) — same pattern as
  the assignment path and `agent/handler.go` ownership checks. Do NOT use the bare pool for
  RLS-governed access (memory `force-rls-superuser-test-masking`).
- Server-pipeline writes (status transitions during generation) run on the server pool
  (`app.current_role='server'`) — accept a `conn`/pool param so the caller (G2-S3) chooses.
  Keep the repo connection-source-agnostic: take the queryer as a parameter.
- Parameterized queries only. No string interpolation of values.

### Scope guards

- Only `course_nodes` and the `course_node_id` side of `node_chats`. The admin
  `course_drafts`/`draft_nodes` repo is G2-S2-T3 (separate worker, separate file).
- No LayeredRunner, no poller, no prompt logic, no HTTP handler — those are G2-S3.
