## Design (how — the mandate)

Real-Postgres integration tests for the admin draft repository (G2-S2-T3). **No mocks**.
Same idiom: `//go:build integration`, `VALORY_TEST_DATABASE_URL`, `dbpkg.IntegrationPool(t)`,
`-p 1` (memory `valory-db-test-drift`). Schema from migration `022`.

### Required coverage

1. **Draft CRUD** — `CreateDraft` (asserts the implicit `root` draft node is seeded, api-sse
   §10.2); `GetDraft`; `ListDrafts` with `status` filter + cursor pagination; `DeleteDraft`
   refuses a `published` draft and succeeds on a `draft`, cascading to `draft_nodes` +
   `node_chats`.
2. **Draft node CRUD** — create a draft tree chain; list by type/parent; ordering; JSONB
   payload round-trip; `SetDraftCurrentLayer`.
3. **Atomic status transition** — `TransitionDraftNodeStatus` true on match, false on stale.
4. **Layer aggregate** — mixed-status layer counts.
5. **node_chats (draft side)** — append + list in order; cascade-delete with the draft node.
6. **RLS isolation — the critical facet (memory `force-rls-superuser-test-masking`):** all
   assertions run **under `SET ROLE valory_app`** with `app.current_user_id` +
   `app.current_role='admin'`:
   - admin A reads/affects only their own drafts and draft nodes;
   - admin B canNOT read admin A's drafts (cross-admin denial → 0 rows);
   - a `student`-role connection canNOT read any draft/draft_node (drafts are admin-only);
   - server role can write.
   Use a `SET ROLE valory_app` helper (mirror `verifyValoryAppGrants` in
   `internal/user/integration_test.go`). Assertions made as superuser are INVALID.
