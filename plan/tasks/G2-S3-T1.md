- **Artifact path:** `internal/agent/node_chair.go` (new), `internal/agent/repository.go` (extend);

## Design (how — the mandate)

This is the **foundation** the LayeredRunner (T2) and both HITL handlers (T3/T4) build on. Two
cohesive pieces, both in package `agent`:

### A. Chair node generalisation (`internal/agent/node_chair.go`)
Generalise the two existing Chair entry points (`GenerateSyllabus` at `chair.go:131`,
`GenerateSyllabusFromParams` at `chair.go:191`) into a node-scoped model per
[knowledge-tree-api-sse.md §6](../../docs/design/knowledge-tree-api-sse.md). Add (as methods on
`Chair`, or a `NodeChair` wrapping `Chair` — match existing style):

```go
func (c *Chair) GenerateNode(ctx, actorID, contextID uuid.UUID, nodeType, topic, level string,
    parameters json.RawMessage, priorContext []NodeChatMessage) (json.RawMessage, error)
func (c *Chair) RefineNode(ctx, actorID, contextID uuid.UUID, nodeType string,
    existingPayload json.RawMessage, chatHistory []NodeChatMessage) (json.RawMessage, error)
type NodeChatMessage struct { Role, Content string }
```
- `contextID` is `course_id` (student) or `draft_id` (admin); `actorID` is `student_id` or
  `admin_id`. Token usage is charged via `ThrottledClient` against `agent_token_usage` using
  `(student_id, course_id)` (student) or `(admin_id, draft_id)` (admin) — the relaxed schema
  from migration 022 (data-model §4.7). **Do not duplicate the ThrottledClient UPSERT** —
  parameterise the context at call time.
- Per-`node_type` system prompts (`syllabus`, `section_goal`, `concept`, `content`) following the
  pattern of `assignmentSyllabusPrompt`/`syllabusSystemPrompt`/`intakeSystemPrompt`
  (api-sse §6.3). `content` prompt: AsciiDoc, max 500 lines, `include::` composition (CLAUDE.md).
- `RefineNode` appends `existingPayload` + full `chatHistory` so the Chair revises without losing
  context.
- **Do not** modify the existing flat-course `GenerateSyllabus`/`GenerateSyllabusFromParams`
  (coexistence — flat courses keep working).

### B. Agent-repo extensions (`internal/agent/repository.go`)
Add the durable plumbing both the runner and the admin SSE need (data-model §4.8, api-sse §5.3):
- `GetEventsAfterForDraft(ctx, draftID, afterEventID uuid.UUID) ([]PipelineEvent, error)` — the
  `draft_id`-scoped overload of `GetEventsAfter` (join `pipeline_events`→`agent_runs` on
  `agent_run_id` filter `draft_id`). Leave the existing `GetEventsAfter(courseID,...)` unchanged.
- An `agent_runs` create path that sets `draft_id` (course_id NULL) for admin runs, honoring the
  `agent_runs_context_check` CHECK (exactly one of course_id/draft_id). The existing course-id
  create path is unchanged.
- A node-scoped pipeline-event emit helper for the new event types (api-sse §5.3.5 +
  state-machine §10: `node_generating`, `node_ready`, `node_approved`, `node_rejected`,
  `node_error`, `layer_awaiting_expand`, and the 11 `layer_*` events) — a thin wrapper over the
  existing event-insert so T2/T3/T4 emit consistently.

## Constraints
- pgx, `context.Context` first; **parameterized queries only**; RLS-governed access takes the
  caller's `db.Querier`/conn (D12). Server-pool writes carry `app.current_role='server'`.
- No HTTP handler, no poller/runner, no prompt-driven generation loop here — those are T2/T3/T4.
- Annotate touched/added functions `@{"req", ["REQ-AGENT-0nn", ...]}` (read
  `internal/agent/requirements/REQ-AGENT-027..060.json` to bind IDs; node-Chair + token =
  REQ-AGENT-0xx; SSE/draft events = REQ-AGENT-0xx).
- Go toolchain `/usr/local/go/bin` → `export PATH=/usr/local/go/bin:$PATH`; `go build ./...` +
  `go vet ./...` clean before returning.
