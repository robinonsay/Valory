## Design (how — the mandate)

Build the poller-driven, layer-by-layer generation engine for the **student `course_nodes`
path** per [layered-generation-state-machine.md](../../docs/design/layered-generation-state-machine.md)
(§4 state machine, §5 runner, §6 durability, §8.3 token budget, §9 sequence). Backend only.

### `internal/agent/layered_runner.go` (new) — `LayeredRunner`
Struct holding the pool, tree repository (G2-S2-T2), `Chair` (T1), reviewer, and config service.

- `GenerateLayer(ctx, runID, courseID, studentID uuid.UUID, layer NodeType) error` — generate
  all `pending`/`rejected` nodes at `layer` for the course. Intra-layer parallelism is allowed
  (bounded). **Per D15: generate each node's initial content via `Chair.GenerateNode` (T1 — the
  node-type-aware prompts), then run the existing reviewer correction/escalation loop for
  quality** (reuse the review/correct/escalate machinery from `runReviewLoop`; do NOT call
  `professor.GenerateSection` for tree nodes). Transition each node
  `pending/rejected → generating → awaiting_review` via the tree repo's atomic test-and-set.
  When the layer is settled (no `pending`/`generating` left; ≥1 `approved`), set
  `courses.status='awaiting_layer_approval'` + `current_layer=<layer>` and emit
  `layer_awaiting_review` (via T1 `EmitNodeEvent`). If all nodes `failed`, emit
  `layer_generation_failed` and halt. **All writes on the server pool (D12).**
- `ExpandToNextLayer(ctx, courseID uuid.UUID, currentLayer NodeType) error` — **called by the
  HTTP handler (T3), NOT the poller.** Precondition: `pending_count==0 && approved_count>0` for
  `currentLayer` (else return a conflict error the handler maps to 409). Insert the child nodes
  for the next layer (`status='pending'`) idempotently (`ON CONFLICT (course_id,node_type,
  ordering) DO NOTHING`), set `courses.status='generating'` + `current_layer=<next>`. Return
  `ErrTreeComplete` when `currentLayer=='content'`.
- `seedTreeAndGenerateRoot(ctx, courseID, studentID)` — on first activation of a tree-mode
  course: insert the `root` node `approved` (payload = student topic/intent); insert the
  `syllabus` node **pre-seeded `approved`** from the already-approved flat syllabus (§7/§9 — no
  HITL gate at root/syllabus); insert `section_goal` children `pending`; set
  `current_layer='section_goal'`, `status='generating'`. The first HITL gate is section_goal.
- **Per-layer token budget (D14)** — before each node generation, if
  `per_layer_token_budget>0` and `agent_token_usage.total + est > budget`, transition the node
  `failed` with reason `token_budget_exceeded` and emit escalation (state-machine §8.3). The
  global `per_student_token_limit` still applies via `ThrottledClient`.
- **Stuck-node recovery** — nodes `generating` with `updated_at < now()-10min` are reset to
  `pending` before dispatch (§6.3).

### `internal/agent/runner.go` (integrate)
- Add a `pollLayeredGeneration` ticker (30s) that finds tree-mode courses with
  `status IN ('generating','awaiting_regeneration')` and a `current_layer`, runs the stuck-node
  reset, and dispatches `GenerateLayer` per course. **It does NOT call `ExpandToNextLayer`**
  (that's the handler's job, D11/§4.3).
- Branch `pollAndGenerate` on `tree_mode`: `true → seedTreeAndGenerateRoot`; `false →
  RunContentGeneration` (unchanged). `ListUntriggeredApprovals` returns the `tree_mode` flag
  (one new field; backward compatible).
- Guard `pollFeedback` with `AND c.tree_mode = false` so the flat keyword-feedback loop skips
  tree courses (§5.5).
- Add the new `course_status` handling (`awaiting_layer_approval`, `awaiting_regeneration`) and
  reuse the new `agent_run_type='tree_layer_generation'`.

### Constraints
- **Do NOT modify** `generateAllSections`/`runReviewLoop`'s flat behavior — flat courses
  (`tree_mode=false`) must be byte-for-byte unaffected. You may extract/reuse the review-loop
  sub-logic, but the flat entrypoints stay intact.
- All RLS-governed writes on the **server pool** (`app.current_role='server'`, D12). Tree reads
  via the tree repo (G2-S2-T2) taking the server conn.
- `Chair.GenerateNode` takes `isDraftContext bool` (T1 deviation) — pass `false` (student).
- Parameterized queries only; `context.Context` first; annotate `@{"req", [...]}`.
- Go toolchain `/usr/local/go/bin` → `export PATH=/usr/local/go/bin:$PATH`; `go build ./...` +
  `go vet ./...` clean. Do NOT rebuild/stage the `server` binary.
