## Design (how — the mandate)

Implement the **student-building** HITL surface per
[knowledge-tree-api-sse.md §5.2](../../docs/design/knowledge-tree-api-sse.md) (and §5.3 SSE).
Mount under the existing student group `/api/v1/courses/{courseId}` (the `authMW`
session+consent group + `security.CSRFMiddleware`, near `cmd/server/main.go:446-468`). Reuse the
existing pipeline-events SSE at `GET /courses/{courseId}/events` — no new SSE endpoint needed
(node events flow through the same `pipeline_events` stream, distinguished by `event_type`).

### Endpoints (exact paths, methods, codes — api-sse §5.2)
- `GET  /courses/{courseId}/nodes` (+ `node_type`/`parent_id` filters) → 200 node list.
- `POST /courses/{courseId}/nodes/generate` → 202 `{node(generating), run_id}`; optional `hint`
  stored as a `user` `node_chats` row first; background goroutine calls `Chair.GenerateNode`
  (`isDraftContext=false`).
- `POST /courses/{courseId}/nodes/{nodeId}/refine` → 202; `message` (required) stored as `user`
  `node_chats` row; background goroutine calls `Chair.RefineNode`.
- `PATCH /courses/{courseId}/nodes/{nodeId}/approve` → 200; `awaiting_review → approved`. After,
  if the layer is fully settled, emit `layer_awaiting_expand`.
- `PATCH /courses/{courseId}/nodes/{nodeId}/feedback` → 200; **the only rejection path**;
  `feedback` required non-empty (else 400); store as `user` `node_chats` row AND in
  `payload.feedback`; `awaiting_review → rejected`.
- `POST /courses/{courseId}/nodes/{nodeId}/regenerate` → 202; `rejected|failed → generating`.
- `GET  /courses/{courseId}/nodes/{nodeId}/chat` → 200 ordered `node_chats`.
- `POST /courses/{courseId}/layers/{layer}/expand` → 200 `{next_layer, inserted_node_count}`;
  calls `LayeredRunner.ExpandToNextLayer`; map its precondition error → 409
  `LAYER_NOT_FULLY_APPROVED`, `ErrTreeComplete` → 409 `TREE_ALREADY_COMPLETE`, bad layer → 400.

### Security / correctness (binding)
- **Ownership check** on every endpoint: the course must belong to the calling student. Use the
  **request-scoped conn** (carries `app.current_user_id`/`app.current_role='student'`) for the
  ownership read — same pattern as `courseOwnedBy` (`agent/handler.go:674`). 404 (not 403) on a
  course the student doesn't own, to avoid existence leaks (match existing student-surface idiom).
- **D12 — all `course_nodes` writes run on the SERVER pool** after the ownership check passes
  (students are read-only on `course_nodes` post-D10). Status transitions + payload writes use
  the server conn; reads (list/get/chat) use the request-scoped conn (RLS read-own).
- **Concurrency guard (api-sse §10.4):** generate/refine/regenerate do an atomic test-and-set
  to `generating` (tree repo `TransitionNodeStatus`); `rowsAffected!=1` → 409
  `NODE_ALREADY_GENERATING` / `NODE_NOT_REVIEWABLE` / `NODE_NOT_REGENERABLE` as appropriate.
- Background goroutines use a detached `context.Background()` (api-sse §6.4) so a closed HTTP
  conn doesn't cancel generation; each creates an `agent_run` (course-anchored) for event
  anchoring; emit `node_generating` → `node_ready`/`node_error` via `EmitNodeEvent`.
- CSRF applies to POST/PATCH (the group already wraps it); GET is exempt.
- Error envelope matches the existing `writeAgentError` pattern.
