> Level 4 task contract. Owned by `software-lead`. Frontier opener for G2-S4 (final Phase B sprint).

- **Worker:** senior-engineer

- **Artifact path:** `frontend/src/components/tree/*` (new), `frontend/src/composables/useNodeEvents.ts`

## Design (how — the mandate)

Build the **shared** Vue building blocks that both the student flow (T2) and the admin flow (T3)
reuse. Vue 3 Composition API, `<script setup>`, TypeScript. Match existing frontend conventions
(look at `frontend/src/views/admin/CourseDetailView.vue`, the `@/api/client` wrapper, the existing
SSE usage for `/events`, and `renderAsciidoc`). **No router changes, no top-level page views** —
those are T2/T3.

### Deliverables
1. **TypeScript types** (`frontend/src/types/`): node + draft shapes matching the G2-S3 API
   responses exactly — cross-check the Go handlers (`internal/agent/node_handler.go`,
   `internal/admin/draft_handler.go`) and the api-sse design doc. Node: id, course_id/draft_id,
   parent_id, node_type (`root|syllabus|section_goal|concept|content`), ordering, status
   (`pending|generating|awaiting_review|approved|rejected|failed`), payload, timestamps. Draft:
   id, title, topic, level, status, current_layer, timestamps. NodeChatMessage: role, content,
   created_at.
2. **API-client methods** (`frontend/src/api/`): typed wrappers over the existing `client` for
   BOTH surfaces — student (`/courses/{id}/nodes…`, `/layers/{layer}/expand`, `/nodes/{id}/chat`)
   and admin (`/admin/drafts…`, publish, chat). GET needs no CSRF; POST/PATCH/DELETE go through
   the existing CSRF-aware client wrapper. Surface the 409 conflict codes to callers.
3. **`useNodeEvents` SSE composable** (`frontend/src/composables/useNodeEvents.ts`): subscribes
   to the event stream (student reuses `GET /courses/{id}/events`; admin uses
   `GET /admin/drafts/{id}/events`) and exposes reactive node/layer state. Handle the node_*
   (`node_generating`, `node_ready`, `node_approved`, `node_rejected`, `node_error`,
   `layer_awaiting_expand`) and `layer_*` event types. Reconnect / `?after=<eventId>` resumption
   like the existing SSE consumer; clean up on unmount (respect component lifecycle).
4. **Components** (`frontend/src/components/tree/`):
   - a **tree/layer view** that renders nodes grouped by layer with status badges;
   - a **node card** with the content (AsciiDoc via the existing `renderAsciidoc`/DOMPurify
     pipeline for `content` nodes; structured display for section_goal/concept JSON) + the HITL
     controls (approve / feedback[with required comment] / regenerate) + a per-node **chat panel**
     (lists `node_chats`, sends refine messages);
   - a **layer expand** control (enabled when the layer is fully approved; calls the expand
     endpoint; surfaces the 409 conflict states).
   The components take the API methods + event state via props/injection so they are
   actor-agnostic (the same components work for student course nodes and admin draft nodes — the
   parent view supplies the right API binding).

### Constraints
- Reuse the existing AsciiDoc renderer (`renderAsciidoc`) — do NOT add a second renderer; content
  is sanitised via the existing DOMPurify path.
- No backend changes. No router changes. No top-level page views (T2/T3 own those).
- Build + typecheck clean: run the frontend `npm`/`pnpm` build + `vue-tsc` and the existing vitest
  suite (must stay green) before returning. (Component tests for the new pieces are T4 — but the
  suite must not regress.)
- Annotate components/composables per the frontend tracing convention (`// @{"req": [...]}`),
  REQ-SYS-073 / REQ-SYS-077 + any REQ-FEADMIN you author.

## Acceptance (done-criteria)
- [ ] Types match the G2-S3 API responses field-for-field (cross-checked against the Go handlers).
- [ ] API-client methods for both student node + admin draft surfaces; CSRF on mutating; 409
      codes surfaced.
- [ ] `useNodeEvents` subscribes/reconnects/cleans-up and exposes reactive node+layer state for
      all node_*/layer_* event types.
- [ ] Tree view + node card (approve/feedback/regenerate + chat) + expand control implemented,
      actor-agnostic (reused by both T2 and T3); AsciiDoc via existing `renderAsciidoc`.
- [ ] Frontend builds + typechecks clean; existing vitest suite still green; no router/view/backend
      changes.
