# G2-S4-T2 — Student interactive build flow (tree_mode discriminator + student route)

> Level 4 task contract. Owned by `software-lead`. Second task of G2-S4 (final Phase B sprint).

- **Worker:** senior-engineer
- **Verifier (acceptance gate):** SQE + Systems Engineer → (batched) Senior SQE
- **Depends on:** G2-S4-T1 (shared tree UI foundation — DONE, committed at HEAD)
- **Artifact path:** `frontend/src/views/**` (new student tree-build view + its `.test.ts` if you
  add one — but full component/e2e tests are T4, so only add a minimal smoke test if it helps you;
  do not regress the suite), `frontend/src/router/index.ts` (student route), and the frontend

## Design (how — the mandate)

Wire the T1 shared components into the **student** "build-your-own course" experience. A course
now has a `tree_mode` boolean: `tree_mode=false` is the existing flat flow (intake → syllabus →
generating → hub → sections) and **must stay byte-for-byte unchanged**; `tree_mode=true` routes
the student into a new **interactive layer-by-layer build view** driven by the G2-S3 student HITL
API + SSE, using T1's `TreeView` / `NodeCard` / `LayerExpandControl` / `useNodeEvents` /
`api/tree.ts`.

### What you build
1. **`tree_mode` discriminator (no backend changes — backend is FROZEN this sprint).**
   - The authoritative source is `GET /courses/{id}` (the `CourseDetail` response carries
     `tree_mode` — confirm the Go handler / response actually includes it; if the field is absent
     from the wire, return `blocked` with detail rather than changing the backend).
   - Add `tree_mode` to the relevant frontend course type(s) (`frontend/src/types/` —
     `CourseDetail` and, if it carries it, the dashboard list item type). Do NOT invent fields the
     backend doesn't send.
   - Routing decision: in `CourseDashboardView.vue`'s `navigateToCourse` (the status→route map),
     a `tree_mode=true` course must land in the new build view instead of the flat
     intake/syllabus/generating/hub routes. **Check whether the student course-LIST endpoint
     (`GET /courses`) returns `tree_mode`.** If it does, switch at navigation. If it does NOT
     (backend frozen — you cannot add it to the list), make the new build route the landing for
     such courses by having the build view itself fetch `GET /courses/{id}`, confirm `tree_mode`,
     and otherwise `replace`-redirect to the correct flat route. Pick the approach that needs no
     backend change and keeps the flat path untouched; document which you chose and why.
2. **Student tree-build view** (`frontend/src/views/` — e.g. `CourseBuildView.vue`): loads the
   course + its nodes (`listCourseNodes` from T1's `api/tree.ts`), subscribes to live updates via
   `useNodeEvents` (student stream `GET /courses/{id}/events`), renders T1's `TreeView`, and wires
   the actor-agnostic callbacks to the **student** `api/tree.ts` methods: approve / feedback /
   regenerate / refine(chat) / `getCourseNodeChat` / `expandCourseLayer` / (generate if the UX
   needs it). Reflect node/layer status from the SSE composable so the tree updates live as the
   Chair generates. Surface the 409 conflict states (e.g. `LAYER_NOT_FULLY_APPROVED`,
   `TREE_ALREADY_COMPLETE`) the components already expose.
3. **Student route** in `frontend/src/router/index.ts`: one new authenticated student route for the
   build view (mirror the existing `courses/:id/...` route style + auth guard). **You own
   `router/index.ts` for this sprint slice; T3 (admin) is serialized after you** — keep your router
   change minimal and additive so T3 can add its admin routes cleanly on top.

### Constraints
- **Backend FROZEN** — consume only the live G2-S3 student API/SSE. No Go changes. If a needed
  field/endpoint is missing, return `blocked` (do not work around it by editing the backend).
- **Flat (`tree_mode=false`) flow unchanged** — the existing intake/syllabus/generating/hub/section
  reader path must behave exactly as before. Prove it (the existing vitest for those views stays
  green; no behavioral edits to them beyond the navigation switch).
- **Reuse T1** — do NOT duplicate tree rendering / SSE / API logic; import from
  `@/components/tree/*`, `@/composables/useNodeEvents`, `@/api/tree`. Reuse the existing
  `renderAsciidoc`/DOMPurify path (already inside T1's `NodeCard`).
- Vue 3 `<script setup>` + TS; match existing student-view conventions (look at `CourseHubView.vue`,
  `CourseDashboardView.vue`, `SyllabusView.vue`). CSRF: mutations already go through T1's client.
- Build + `vue-tsc` typecheck clean; existing vitest suite stays green (full component tests are
  T4). Annotate new code per the tracing convention `// @{"req": ["REQ-SYS-073", ...]}`.

## Acceptance (done-criteria)
- [ ] `tree_mode` added to the frontend course type(s) from the real `GET /courses/{id}` payload;
      no invented fields; no backend changes.
- [ ] A `tree_mode=true` course routes the student into the new interactive build view; a
      `tree_mode=false` course still follows the exact existing flat flow (unchanged).
- [ ] Build view loads nodes + subscribes via `useNodeEvents`, renders T1's `TreeView`, and wires
      approve/feedback/regenerate/refine-chat/expand to the student `api/tree.ts` methods; live SSE
      status reflected; 409 states surfaced.
- [ ] One additive student route in `router/index.ts` (auth-guarded), minimal so T3 can extend.
- [ ] Frontend builds + typechecks clean; existing vitest suite still green; no backend changes;
      flat-flow views not behaviorally altered.
