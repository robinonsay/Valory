## Design (how — the mandate)
Build the admin "author-and-assign" experience over the G2-S3 **admin draft** API + SSE, reusing
the accepted T1 shared components. The admin builds a course *draft* tree interactively with the
Chair (same per-node approve / feedback / regenerate / chat + layer-expand experience as the
student build view), then **publishes** it, which produces a draft-backed assignment the existing
assignment flow assigns to students (the publish→`course_nodes` copy is already implemented +
tested server-side in G2-S3-T4/T6). Do NOT change the backend (frozen).

### Reuse (do NOT reimplement)
- T1 components `@/components/tree/{TreeView,NodeCard,LayerExpandControl}.vue`,
  `@/composables/useNodeEvents` (admin SSE stream `GET /admin/drafts/{id}/events`),
  `@/api/tree` **admin methods** (`createDraft`, `listDrafts`, `getDraft`, `deleteDraft`,
  `generateDraftNode`, `refineDraftNode`, `approveDraftNode`, `feedbackDraftNode`,
  `regenerateDraftNode`, `getDraftNodeChat`, `expandDraftLayer`, `publishDraft`), and `@/types/tree`.
- The T1 tree components are actor-agnostic — bind them to the **admin draft** API callbacks (the
  draft editor is the admin analogue of T2's `CourseBuildView`, pointed at the draft endpoints +
  admin SSE stream, plus a publish action).
- Match existing admin-view conventions: look at `AdminAssignmentsView.vue`,
  `AdminAssignmentDetailView.vue`, `CourseDetailView.vue`, and `frontend/src/layouts/AdminLayout.vue`.

### Deliverables
1. **Draft list view** (`frontend/src/views/admin/`, e.g. `DraftListView.vue`): lists the admin's
   drafts (`listDrafts`, with the status filter + cursor pagination it supports), a **create-draft**
   action (form/modal capturing title + topic + level → `createDraft`, which seeds the draft + root
   node), navigate-to-editor, and **delete** (`deleteDraft`; surface 409 `DRAFT_ALREADY_PUBLISHED`).
2. **Draft editor view** (`frontend/src/views/admin/`, e.g. `DraftEditorView.vue`): loads the draft
   + its nodes (`getDraft`), subscribes to the **admin** SSE stream via `useNodeEvents`, renders
   T1's `TreeView`, and wires approve / feedback / regenerate / refine-chat / `getDraftNodeChat` /
   `expandDraftLayer` to the **admin draft** `@/api/tree` methods. Live SSE status reflected;
   409 states surfaced (`LAYER_NOT_FULLY_APPROVED`, `TREE_ALREADY_COMPLETE`, etc.). Admin can
   **preview the syllabus + chat** with the Chair per node before publishing.
3. **Publish → assign**: a **Publish** action (`publishDraft`) enabled only when the tree is
   complete/all-approved; surface the 409 `DRAFT_HAS_UNAPPROVED_NODES` precondition. `publishDraft`
   returns the created/updated **assignment id** — on success, route the admin to the existing
   assignment flow (`/admin/assignments/{assignmentId}` → `AdminAssignmentDetailView`) so they
   assign students there (the server does the draft→`course_nodes` copy per assigned student). Do
   NOT build a parallel assign UI — reuse the existing assignment views.
4. **Admin routes** (`frontend/src/router/index.ts`): additive routes under the existing `/admin`
   children block (e.g. `drafts` → list, `drafts/:id` → editor), `requiresAuth: true,
   requiredRole: 'admin'`, mirroring the existing admin child routes. T2 already added the student
   `courses/:id/build` route — your admin routes must not conflict with it.
5. **Reachable from the admin area**: a nav entry (AdminLayout sidebar link to the draft list, or a
   "Create tree course" entry point near `AdminAssignmentsView`). Keep it consistent with existing
   admin nav.

### Constraints
- **Backend FROZEN.** Consume only the live G2-S3 admin draft API/SSE. No Go changes. If a needed
  field/endpoint is genuinely missing, return `blocked` with evidence (file:line) — do NOT edit the
  backend (that is what happened with T5; surface, don't work around).
- **Do not disturb other admin views** (Oversight, CourseDetail, Assignments, Users, Audit, Config)
  beyond an additive nav link. The existing admin vitest suite stays green.
- CSRF: mutating draft calls already go through T1's CSRF-aware client — do not bypass with raw fetch.
- Vue 3 `<script setup lang="ts">`, TS; match admin-view idiom/naming/comments. Tracing annotations
  `// @{"req": ["REQ-SYS-077", ...]}` (+ your REQ-FEADMIN-710 if authored).
- Full component/e2e tests are T4 — you only must NOT regress the suite (a tiny smoke test is fine).
- Build + `vue-tsc` typecheck clean; existing vitest green. Report exact commands + counts.

## Acceptance (done-criteria)

- [ ] Draft editor: loads draft+nodes, admin SSE via `useNodeEvents`, renders T1 `TreeView`, wires

      with T2's student route; other admin views untouched (beyond a nav link).
- [ ] Frontend builds + typechecks clean; existing vitest suite green; no backend changes.
