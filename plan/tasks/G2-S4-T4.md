## Design (how — the mandate)
Add test coverage for the interactive knowledge-tree UI built in T1–T3. **Two tiers:**

### Tier 1 — vitest component tests (PRIMARY deliverable; MUST be green; zero cost)
Mock the network seam (`@/api/tree`) and the SSE seam (`@/composables/useNodeEvents`) — **no real
backend, no paid Anthropic calls, no real EventSource.** Follow the existing component-test idiom
(look at `frontend/src/views/CourseHubView.test.ts`, `CourseDashboardView.test.ts`,
`admin/CourseDetailView.test.ts`; use `@vue/test-utils` + vitest as the suite already does). Cover:

- **TreeView** (`@/components/tree/TreeView.vue`): groups nodes by layer in canonical order;
  renders a NodeCard per node; reflects status from the injected status map.
- **NodeCard** (`@/components/tree/NodeCard.vue`): a `content` node renders via the existing
  `renderAsciidoc` path (assert sanitised HTML output, not a second renderer); `section_goal`/
  `concept` render structured JSON; **approve** fires the callback; **feedback** requires a
  non-empty comment (empty comment is blocked / does not call the API); **regenerate** fires;
  the **chat panel** loads history and sends a refine message.
- **LayerExpandControl** (`@/components/tree/LayerExpandControl.vue`): expand enabled only when the
  layer is fully approved; calls the expand callback; surfaces the 409 conflict codes
  (`LAYER_NOT_FULLY_APPROVED`, `TREE_ALREADY_COMPLETE`) as user-visible messages.
- **CourseBuildView** (student, `@/views/CourseBuildView.vue`): loads nodes; binds TreeView to the
  student `@/api/tree` callbacks; reflects live SSE status; the mount-guard redirect fires when
  `tree_mode` is false (and does NOT loop). Also cover the `CourseDashboardView` routing switch:
  a `tree_mode=true` course routes to the build view; `tree_mode=false` keeps the existing flat
  route (assert the flat map is unchanged).
- **DraftListView** (admin): list with status filter + cursor; create requires a non-empty title
  (matches the backend contract) → `createDraft`; delete surfaces 409 `DRAFT_ALREADY_PUBLISHED`.
- **DraftEditorView** (admin): loads draft + nodes; binds TreeView to the admin draft callbacks;
  **publish gating** — disabled unless every node is approved (a new draft with only an unapproved
  root is NOT publishable); publish surfaces 409 `DRAFT_HAS_UNAPPROVED_NODES`; publish success
  navigates to `/admin/assignments/{assignment_id}` using the returned id.
- (Optional but valuable) **useNodeEvents**: a focused unit test of its event reducer by mocking
  `useSSE` — assert node_*/layer_* events update the reactive state and `onUnmounted` cleans up.

Tests must be **non-vacuous** (assert real behavior, with positive controls — e.g. prove the
feedback-empty case actually blocks the call vs. the non-empty case calling it). Carry
`// @{"verifies": ["REQ-SYS-073", "REQ-SYS-077", "REQ-FEADMIN-709", "REQ-FEADMIN-710", ...]}`
annotations. The FULL vitest suite must stay green (currently 595 passing) and grow by your tests.

### Tier 2 — Playwright e2e specs (authored; cost-GATED — do NOT run the paid journey)
Examine `frontend/e2e/` + `frontend/playwright.config.ts` (two projects: `chromium` and the **paid**
`journey`). Author e2e specs for the two happy-path flows (student build, admin author→publish) that
follow the existing e2e pattern.
- **Cost rule (binding):** do NOT run `test:e2e:journey` (it hits the paid Anthropic API; memory
  `valory-stack-rebuild-before-e2e` — it has burned paid runs before). Only run an e2e project if it
  works against a **stubbed/mocked** backend with NO paid calls (e.g. Playwright route-mocking or
  the existing chromium project if it is already non-paid). If running requires the real stack, do
  NOT run it here — author the spec, make it typecheck/lint, and **document the run steps** (rebuild
  the prod stack first per the memory, then `npm run test:e2e`). State clearly in your return which
  e2e you ran (if any) vs. authored-but-gated.
- If authoring meaningful e2e against a stub is not feasible without guesswork, prefer to **skip
  Tier 2 with a clear written rationale** rather than commit unrunnable/unverified e2e — Tier 1 is
  the deliverable that gates this task.

## Constraints
- Test-only task: add `*.test.ts` (+ optional `e2e/*.spec.ts`). Do NOT modify the components/views
  under test or any non-test source. If a real bug in T1–T3 blocks a test, return `blocked` with

- Run from the frontend dir with its package manager (check the lockfile): `npm test` (vitest) must
  pass; `vue-tsc --noEmit` clean. Report exact commands + counts (before/after test count).
