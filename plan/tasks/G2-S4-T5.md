# G2-S4-T5 — Backend: expose `tree_mode` in the course API responses

> Level 4 task contract. Owned by `software-lead`. Added mid-sprint (Lead decision **D16**) to
> unblock G2-S4-T2/T3 — the G2-S3 student/admin course API omitted the `tree_mode` discriminator
> the interactive-tree frontend requires.

- **Worker:** senior-engineer
- **Verifier (acceptance gate):** SQE + Systems Engineer → (batched) Senior SQE
- **Depends on:** nothing (the `tree_mode` column already exists in the `courses` table from
  migration 022; this only surfaces it on the wire). **Unblocks G2-S4-T2 and G2-S4-T3.**
- **Artifact path:** `internal/course/repository.go`, `internal/course/handler.go`, and the
  course-package test file(s) you extend. Summary under `plan/artifacts/G2-S4-T5/`.

## Why (the gap)
The `courses` table has a `tree_mode boolean` column (added in `migrations/022_tree_generation.sql`;
already read by the `agent` package — see `internal/agent/repository.go:44`). But the **`course`
package never exposes it**: `CourseRow` (`internal/course/repository.go:24-41`) has no `TreeMode`
field, and `courseToResponse` (`internal/course/handler.go:575-605`) does not emit `tree_mode`.
So `GET /api/v1/courses/{id}` and `GET /api/v1/courses` give the frontend no way to tell a
tree-mode course from a flat one. The student build flow (T2) and admin flow (T3) both need it.

## Design (how — the mandate)
Minimal, **additive**, behavior-preserving exposure of the existing column. NO new logic, NO
schema change (the column exists), NO change to who can see what (it is a non-sensitive boolean on
a course the caller already reads).

1. **`internal/course/repository.go`** — add `TreeMode bool` to `CourseRow`. Then update **every
   query that scans into a `CourseRow`** to (a) include `tree_mode` (or `c.tree_mode` for the
   JOINed admin variant) in the SELECT column list and (b) add the matching `&row.TreeMode` to the
   `rows.Scan(...)`/`row.Scan(...)` call, **in the same column order**. Audit the whole file — the
   known sites are `GetCourseByID`, `getCourseByIDTx`, `Transition`, `TransitionTx`, and
   `ListCourses` (including its admin JOIN path that also selects `student_username`/`student_email`),
   but **grep for every `CourseRow{` / `.Scan(` that populates a `CourseRow` and fix all of them** —
   a missed scan site or a column/scan-order mismatch is the classic bug here and will break course
   loading at runtime. Keep the SELECT column ordering and the Scan argument ordering in lockstep.
2. **`internal/course/handler.go`** — in `courseToResponse`, add `"tree_mode": course.TreeMode` to
   the response map (a plain bool, always present — not behind a nil-guard, since it is a non-pointer
   bool with a meaningful `false` default). This flows to both `getCourse` and `listCourses`.
3. **Tests** — extend the course package's existing tests so the regression is guarded: assert
   `tree_mode` is present in the `getCourse` response and reflects the row value (true for a
   tree-mode course, false for a flat one). Prefer the existing test style/harness in the package.
   If the package has integration tests (real Postgres, `//go:build integration`,
   `VALORY_TEST_DATABASE_URL`, `-p 1`, no DB mocks, RLS under `SET ROLE valory_app`), add the
   assertion there; otherwise extend the existing unit/handler test. Do not introduce DB mocks.

## Constraints
- Touch ONLY `internal/course/` (repository.go, handler.go, its tests). Do not change other
  packages, the migration, or the frontend. The `agent`/`admin` packages already read `tree_mode`
  independently — leave them alone.
- Behavior-preserving: every existing course-package test must still pass. The only observable
  change is the new `tree_mode` field in course responses.
- Idiomatic Go, explicit error handling, `context.Context` preserved, parameterized queries only.
- Build + `go vet` clean; run the course-package tests (unit; and integration if the DB harness is
  available — `PATH` must include `/usr/local/go/bin` and set `VALORY_TEST_DATABASE_URL`, run with
  `-p 1`). Report what you ran and the result.
- Annotate any new test with `// @{"verifies": ["REQ-SYS-073", "REQ-SYS-077"]}` and keep existing
  `@{"req":...}` annotations intact.

## Acceptance (done-criteria)
- [ ] `CourseRow.TreeMode` added; **every** query scanning a `CourseRow` selects+scans `tree_mode`
      with matching column/scan order (all sites audited, none missed).
- [ ] `courseToResponse` emits `tree_mode` (bool, always present); flows to GET `/courses/{id}` and

- [ ] A test asserts `tree_mode` is present and correct (true vs false); no DB mocks.
- [ ] All existing course-package tests still pass; `go build` + `go vet` clean; no changes outside
