> Level 4 task contract (design facet). Owned by `software-lead`. Frontier opener of G3-S1;
> authoritative design for T2 (requirements), T3 (migration+eligibility), T4 (runner dispatch).

- **Worker:** design-author
- **Verifier (acceptance gate):** Senior SQE
- **Depends on:** — (frontier opener)
- **Artifact path:** `docs/design/generation-run-lifecycle.md`

## Design mandate (what the TDD must specify)

Produce the authoritative technical design for a disciplined generation **run lifecycle** that
replaces today's fire-and-forget, poll-driven model. Ground it in the observed failure: `pollAndGenerate`
re-derives eligibility every 30s from course+run status alone, with no retry budget/backoff, no
terminal failure, and an inconsistent in-flight guard (tree has a `sync.Map`; flat relies on the
`agent_runs.status` default `'running'`) → **925 failed `content_generation` runs in 10h**. Read the
current implementation first: `internal/agent/runner.go` (`pollAndGenerate`, `RunContentGeneration`,
`generateAllSections`, `runReviewLoop`, the layered poller + `inFlightLayered`),
`internal/agent/repository.go` (`ListUntriggeredApprovals`, `CreateRun`, `SetRunStatus`),
`internal/agent/professor.go` (`searchInternet` ordering), and the `agent_runs` / `courses` schema.

The TDD must define:

1. **Run state machine.** Explicit states + transitions for a generation run (e.g. `running →
   succeeded | failed`; with a course-level terminal `generation_failed`). Define what sets each,
   when `completed_at` is stamped, and how this maps onto the existing `agent_runs.status` values
   (additive — don't break `terminated`/existing consumers).
2. **Retry policy (declarative).** A **backoff window** (config key + default, e.g. 10 min) and a
   **max consecutive attempts** (config key + default, e.g. 5) after which the course transitions to
   the **terminal `generation_failed`** state the poller never selects. Specify how "consecutive
   failures since last success" is computed. Reconcile with REQ-AGENT-003 ("a failed run does not
   *permanently* block retry") → bounded auto-retry then an explicit manual re-trigger gate.
3. **Idempotent, unified dispatch.** How dispatch **claims** a run so a course can never have two
   concurrent runs — flat and tree using **one** mechanism (remove the divergence). Specify whether
   the claim is the atomic `CreateRun`→`running` (made race-safe) and/or a process-level in-flight
   registry, and exactly what guarantees "exactly one run under a forced race."
4. **Eligibility rule.** The precise `ListUntriggeredApprovals` predicate: exclude running/completed
   (unchanged), failed-within-backoff, terminal `generation_failed`, and max-attempts-exhausted
   (the last → transition to terminal). Keep the `(CASE … END)::agent_run_type` cast and `tree_mode`
   branch.
5. **Cost-safety hook (S1 scope = fail-fast only).** Where the **token-cap pre-flight** sits so a
   capped run fails *before* any per-section Brave/Claude work (today `searchInternet` precedes the
   Claude cap check). The *full* cost gate + Brave accounting is **G3-S2** — T1 only defines the hook
   point + that capped runs do zero per-section paid work.
6. **Event taxonomy + recovery.** Lifecycle events emitted (claim, fail, terminal/abandoned) and how
   an operator/student explicitly recovers a `generation_failed` course.
7. **Backward compatibility + migration shape.** Flat *and* tree on the unified lifecycle; existing
   happy-path generation unchanged; the additive migration 024 shape (status value + eligibility
   index) for T3. Explicitly out of scope: cost accounting (S2), concurrency/resumability (S3).

State binding decisions D17–D20 (plan/sprints/G3-S1.md) as the design's load-bearing choices, or
argue a reasoned deviation. Keep it implementable-exactly (no hand-waving): T3/T4 must be able to
build from it without inventing semantics, and T2 must be able to derive atomic requirements.

## Acceptance (done-criteria)
- [ ] State machine, retry policy (backoff + max-attempts + terminal), idempotent unified claim,
      eligibility predicate, cost-safety hook, event taxonomy, and migration shape all specified
      concretely enough to implement and to test counterfactually.
- [ ] Reconciles REQ-AGENT-003 (bounded retry, not permanent block) and preserves flat+tree + RLS.
- [ ] Config keys (backoff window, max attempts) named with defaults; additive `agent_runs`/`courses`
      changes only.
- [ ] No cost-accounting or concurrency design (deferred to S2/S3) beyond the named hook points.
