## Mandate

Author the L2 requirements that make the T1 design verifiable. Read `docs/design/generation-run-lifecycle.md`
(authoritative) and `plan/sprints/G3-S1.md` (decisions D17–D21). The File/Unit grain for T3 already
references **REQ-AGENT-061..065** — author at least those, with these meanings (refine wording to be
atomic, ≤20 words, WHAT-not-HOW, "shall", ending in a period; schema-valid against
`schemas/requirements.schema.json`):

- **REQ-AGENT-061** — generation migrations self-record + are idempotent (the 021–023 convention).
- **REQ-AGENT-062** — a course that exhausts generation retries enters a terminal failed state the
  scheduler never auto-selects.
- **REQ-AGENT-063** — generation eligibility lookups are index-backed (no full scans at poll cadence).
- **REQ-AGENT-064** — the scheduler shall not start a generation run for a course with a recent
  failed run inside the backoff window, or in the terminal failed state.
- **REQ-AGENT-065** — retry budget counts failed dispatch-level runs per course since last success
  (D21).

Author additionally, as the design warrants (use the next free IDs ≥066):

- **Idempotent dispatch / no double-run** — a course shall never have two concurrent generation runs
  (flat or tree).
- **Bounded retry with backoff** — failed generation auto-retries are spaced by a configurable
  backoff and capped at a configurable max attempts.
- **Cost fail-fast** — a generation run over the token cap shall make no per-section external
  (search or model) call.
- **Recovery** — a terminally-failed course can be explicitly re-triggered (resolve the design's
  **OQ-1**: define the supported recovery action; a bare manual status reset is out of scope or
  explicitly disallowed — state which).

Consider one **L1 `REQ-SYS-*`** capturing the system invariant ("background generation is bounded
and cost-governed") if it adds traceability value; otherwise justify keeping it all L2.

## Constraints
- Each requirement atomic, single behavior, ≤20-word `description` (WHAT, not HOW), "shall", period.
  `rationale` states WHY (not how). Valid `verification_method` enum. `uses` references existing IDs
  only. No ID collisions (check existing REQ-AGENT-* max — G2 went to 060; start at 061). Schema-valid.
- Co-locate L2 in `internal/agent/requirements/`. Do NOT restate design mechanics in `description`.
- Keep the set tight — one requirement per testable behavior; the T3/T4/T5 acceptance criteria and
  Unit docs must each map to one of these IDs.
