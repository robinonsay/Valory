## Mandate — scenarios (each MUST be counterfactual: deleting the guard it covers makes it fail)
Drive behaviour through the real dispatch/repo code, real rows, SET ROLE valory_app. For each,
state in a comment which line/guard the test would catch if removed.

1. **Storm cannot recur — bounded runs (flat AND tree).** Seed a `syllabus_approved` course;
   force generation to fail every attempt (fake transport returns an error/5xx, or token cap —
   pick one path per test). Drive the dispatch path `maxAttempts + N` times. Assert: total
   `agent_runs` rows for the course ≤ `generation_max_attempts`; the course ends in
   `generation_failed`; `ListUntriggeredApprovals(maxAttempts)` no longer returns it.
   *Counterfactual:* without the terminal/max-attempts logic the run count is unbounded / the
   course stays eligible. (REQ-AGENT-064, 067.)
2. **Idempotent dispatch — forced race yields exactly ONE run.** With a course eligible, fire two
   concurrent claims for the same `(course, run_type)` (two goroutines calling the claim path, or
   two `CreateRun`s). Assert exactly one `agent_runs` row is created and the loser returns
   `ErrRunAlreadyClaimed` handled as a benign skip (no error surfaced, no second generation
   goroutine). *Counterfactual:* removing the partial-unique-index tolerance / in-flight guard →
   2 rows. (REQ-AGENT-066.)
3. **Backoff spacing.** After a failed dispatch, assert `next_eligible_at ≈ now + backoff` and
   that `ListUntriggeredApprovals` excludes the course until the window elapses; then (set
   `next_eligible_at` into the past, or use a short backoff) assert it becomes eligible again.
   *Counterfactual:* drop the backoff predicate → eligible immediately. (REQ-AGENT-064, 067.)
4. **Max-attempts → terminal `generation_failed` (+ D22).** After `maxAttempts` consecutive
   failures the course is `generation_failed` and the poller excludes it; additionally assert a
   terminally-failed course does NOT block creating a new course (D22 widened
   `courses_single_active_idx`). (REQ-AGENT-062, 064.)
5. **Recovery.** `RecoverGenerationFailed` on a `generation_failed` course returns it to an
   eligible state with `generation_attempt_count` reset and `next_eligible_at` cleared, and it is
   dispatchable again; a bare manual status flip is NOT the supported path (OQ-1). (REQ-AGENT-069.)
6. **tokenCapPreFlight fail-fast — zero paid calls (flat AND tree).** Seed `agent_token_usage`
   over the per-student cap; dispatch. Assert the run is recorded `failed` immediately, the fake
   chair transport made **zero** calls (`transport.Calls == 0` — no Brave/Claude), and backoff
   applies (so it feeds the bounded-retry path, not an infinite hot loop). (REQ-AGENT-068,
   REQ-SYS-074.)
7. **D21/D24 tree reset fires only at the content layer.** Drive a tree course so the content
   (final) layer settles; assert `generation_attempt_count` resets to 0 at that point and NOT
   after the root/section_goal seed. *Counterfactual:* the premature-reset bug (reset in
   `dispatchTreeCourse`) would zero the counter after the root layer. (REQ-AGENT-065.)
8. **Happy-path, no regression.** A flat course whose generation succeeds reaches `status='active'`
   with `generation_attempt_count` reset and the run `completed`; a tree seed reaches
   `awaiting_layer_approval`. Confirms the lifecycle hooks did not break the success path.
